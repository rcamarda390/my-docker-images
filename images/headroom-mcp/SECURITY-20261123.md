# Headroom 0.45.0 Wolfi baseline Xray remediation

The November 23 CSV contains 36 rows for 21 distinct Xray advisories.
Both reported layer digests occur in the Docker Hub linux/amd64 manifest
for `0.45.0-wolfi-v1`,
`sha256:ef441ce91e0036ed5c298e97bc848cd94c1c07ebc6b4b7c66dca70b43b7f298e`.
The [shared ledger](../../docs/security/findings.json) preserves every row.
The CSV reports applicability as `Not Covered` and supplies no manifest digest.

| Reported component | Advisories | Treatment for Wolfi v2 |
| --- | --- | --- |
| glibc, loader, POSIX locale, libcrypt `2.44-r6` | CVE-2026-84243, CVE-2026-86805, CVE-2026-89092, CVE-2026-8674, CVE-2026-95818 | Require and assert `2.44-r16` or later for the four matching APKs. Wolfi lists r16 for CVE-2026-84243 and r8 for the other four. |
| CA bundle `20260611-r1` | CVE-2026-91403, CVE-2026-111943 | Retain system trust and require `ca-certificates-bundle >= 20260909-r3`. The Wolfi security database maps both advisories to the CA source package even though the summaries refer to Java and Go. |

The `7f42b6c7…` layer is the pinned Wolfi base's APK database layer.
Publish the verified final filesystem and its updated APK database so the
old package database and superseded base files are absent from the shipped
layers. The image keeps its non-root user, Bedrock/Cline patch, existing
offline settings and Kompress cache.

| Wolfi AgentMemory, AI CLI Runner, Bifrost, GitHub MCP, Gnosis, standalone LiteLLM and Sooperset Atlassian | Final recipes enforce glibc r8 and the CA/zlib floors. Installed glibc r16 or newer and the presence of the inherited package database need exact-artifact checks. |

| Gnosis and Sooperset Atlassian | Their Python recipes assert Pydantic `2.14.2` or later. Gnosis still allows Filelock from `4.2.1` and an unpatched Tokenizers `0.23.3`. Their final transitive version and compiled-copy inventory remain image-specific. |
| Other final runtimes and payloads | Alpine eBay and Docker Socket Proxy and UBI Zeus use other vendors. Scratch and data-only payloads have no Wolfi package database. Debian recipes use their own patches and package trackers. Vendored or compiled copies need separate provenance where the recipe cannot establish versions. |

The live Debian tracker recheck covered 117 pending ledger entries.
Trixie now lists `2.41-12+deb13u5` for the four older glibc CVEs, and
`1:1.3.dfsg+really1.3.1-1+deb13u1` for the reported zlib CVE. These
are Debian replacement candidates that require validation against the
existing Debian carries.

Candidate validation uses the final-image package assertions, the AnyIO,
Tokenizers and Transformers regressions, the Bedrock compatibility test,
the offline proxy smoke test and Trivy. Xray verification requires a scan
of the new digest. Version-based reports may still list the three
source-patched components.
