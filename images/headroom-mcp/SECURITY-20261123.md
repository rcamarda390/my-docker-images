Both reported layer digests occur in the Docker Hub linux/amd64 manifest
for `0.45.0-wolfi-v1`,
`sha256:ef441ce91e0036ed5c298e97bc848cd94c1c07ebc6b4b7c66dca70b43b7f298e`.
The [shared ledger](../../docs/security/findings.json) preserves every row.
The CSV reports applicability as `Not Covered` and supplies no manifest digest.

The live Debian tracker recheck covered 117 pending ledger entries.
Trixie now lists `2.41-12+deb13u5` for the four older glibc CVEs, and
`1:1.3.dfsg+really1.3.1-1+deb13u1` for the reported zlib CVE. These
are Debian replacement candidates that require validation against the
existing Debian carries.

Candidate validation uses the final-image package assertions, the AnyIO,
Tokenizers and Transformers regressions, the Bedrock compatibility test,
the offline proxy smoke test and Trivy. Xray verification requires a scan
of the new digest. Version-based reports may still list the three
source-patched components.

## Wolfi v2 rescan and v3 remediation

The v2 Xray CSV contains two rows. Both point to the filesystem layer
`sha256:d4585a6cfb165834f71682889b061e52cc19fc5087918f1dc173f8590c1c6bdb`,
which matches the published `0.45.0-wolfi-v2` linux/amd64 manifest
`sha256:0f0c872962c636bc0a7790c548a93266d4176cc15f7ae55efebf38a9dde58eef`
in both registries. The other 19 v1 advisory IDs are absent from this
supplied report. The two remaining rows name the original upstream
distribution versions, even though the v2 filesystem contains both
source fixes.

| Finding | v3 treatment |
| --- | --- |
| XRAY-1170984 / AnyIO | AnyIO 4.16.0 is the latest published release at review time. Build `4.16.0+rcamarda1` from the checksum-verified 4.16.0 source with the existing upstream asyncio and Trio backport. The final regression checks that a PathLike uses direct execution. |
| CVE-2026-75104 / Transformers | The 5.24.0 release and reviewed upstream main still lack the checkpoint shard guard. Build `5.17.0+rcamarda1` from the checksum-verified 5.17.0 source. Validate shard names and model subfolders before local or Hub loading. Check resolved local shard paths against the selected checkpoint directory. The regression covers valid nested checkpoints, symlink containment, and cached Hub loading. |

The source changes precede wheel packaging. The installed distribution
metadata and wheel RECORD hashes identify the downstream builds. Xray may
still match the original versions or the all-versions Transformers advisory.
An exact-digest v3 Xray rescan is required to assess scanner status.

The Gnosis and Sooperset Atlassian build locks still resolve AnyIO
`4.14.2`. Their separate runtime checks are needed before applying the
carry. The standalone LiteLLM recipe resolves its proxy dependencies
independently. Neither the Gnosis nor Sooperset lock lists Python
Transformers. Other sibling runtime inventories remain unverified where
their final recipes do not identify the packages. The older Debian
Headroom recipe uses the shared Transformers source guard.
