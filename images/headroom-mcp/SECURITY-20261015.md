# Headroom 0.41.0: repair recursive libc regex crashes

PR: https://github.com/rcamarda390/my-docker-images/pull/73

## Actual new source correction

CVE-2018-20796 and CVE-2019-9192 share the recursive backreference walk in
`posix/regexec.c`. The self-loop check handles only an immediate edge back
to the current node. Published patterns form longer cycles and exhaust the
native stack. Calling this disputed does not prevent the crash.

Add a downstream resource bound of 64 recursive frames. Propagate exhaustion
through both callers and their existing cleanup paths as REG_ESPACE. POSIX
regexec returns that explicit error; GNU re_search/re_match return -2.
Do not convert resource exhaustion into a successful match or REG_NOMATCH.
The public API previously collapsed errors into a nonzero boolean, so preserve
its existing behavior for other errors while exposing REG_ESPACE accurately.

Tradeoff: a valid expression needing more than 64 frames also fails explicitly.
This is a bounded-resource correction, not a complete iterative regex rewrite.
Retire it when an upstream nonrecursive implementation is verified. Other regex
resource-exhaustion classes are not claimed fixed.

## Verification

- Build glibc 2.41 locally from Debian's upstream source tarball. Debian's
  2.41-12+deb13u4 patch archive contains no posix/regexec.c modification.
- Build an otherwise identical unpatched libc as a negative control. Both
  published reproducer families terminate with SIGSEGV (-11). The patched
  library returns REG_ESPACE (12) for both, using its own loader/library path.
- The checked C verifier passes malicious and valid patterns in C and C.UTF-8
  locales, ordinary backreferences, match/no-match and GNU API checks.
- All 36 selected upstream bug-regex1..bug-regex36 tests pass. Glibc also
  automatically included bug-ga2 and tst-vfork3; these fail with write EPERM
  in this sandbox. Do not describe the entire check invocation as passing.
- Local source build omitted the absent non-free manual directory from the
  Debian orig tarball; no runtime source or selected test was skipped for it.
- Docker is unavailable locally. Candidate builds must repeat the tests on
  their actual Debian package roots and run each image's existing smoke/scan.

## Other findings: deeper review and limits

Existing libc resolver/loader/wordexp/iconv fixes, Dash fnmatch rebuild,
Transformers shard-path guard and LiteLLM email-verification patch are retained.
The 53-row report has no installed versions or digest. Source evidence cannot
establish which code Xray scanned, or establish scanner clearance.

GCC CVE-2026-95619: upstream 59d235ffa5a69231eb42e5290d52dc8c90d28b7a
fixes allocation rounding in non-posix_memalign branches. The selected Linux
runtime uses posix_memalign, and existing nine oversized-allocation regressions
exercise that ABI. A new package version alone is not a newly effective fix.

GCC CVE-2026-102010: upstream aaa8351f4d2e636f9680a1f0a8ebc2f0a60611e6
repairs a PBDS template header. Shared-library substitution cannot repair code
already compiled into an ONNX/native wheel. Consumer provenance/rebuild remains
open. Debian lists gcc-14 14.4.0-3 fixed only in Sid; its pool does not provide
matching libstdc++6/libgcc-s1 binaries. Examined GCC 16.2.0-3 packages retain
backward exported symbols and compatible libc dependency floors, but Debian
still lists both CVEs open for gcc-16. Do not upgrade merely for a higher number.

CVE-2019-1010022 concerns x86 thread-control-block/canary placement. Upstream
22850 explicitly describes moving the TCB and per-thread canaries as core
algorithm/ABI hardening work. No verified safe small backport is available.
CVE-2019-1010023/24/25 and CVE-2010-4756 remain open; libc cannot be removed
from this Python/native-extension runtime. No unrelated loader/thread/allocator
redesign is claimed completed by this patch.

Alpine/Wolfi/UBI runtimes do not share this Debian recipe; applicability is not
inferred from a common CVE string. Keep their existing unknown/distribution
review dispositions. Scratch payloads require artifact-specific inspection.

No finding is suppressed or marked scanner-cleared. A new Xray scan of the
exact rebuilt immutable digest is required.
