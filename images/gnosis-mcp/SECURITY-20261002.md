## glibc custom revision

`+rcamarda2` means the second downstream Debian glibc rebuild; it is not an
upstream release or another package. The Debian base remains
`2.41-12+deb13u4`, currently the Trixie version. Its custom revision must
advance when its patch set changes. This change produces
`2.41-12+deb13u4+rcamarda3`, retains every rcamarda2 patch and adds:

| CVE | Upstream fix | Change |
| --- | --- | --- |
| CVE-2026-8674 | 506ea57086bfb9ce3daff1c14246a1cb532aba0a | Check truncated DNS search-list storage against defdname and handle an oversized first entry. Downloaded upstream patch is SHA-256 pinned. |
| CVE-2026-86805 | ed0c137b97eb940b4b64981e84ed806d3276edd9 | Normalize secure-mode ORIGIN paths in place; open exactly the path validated as trusted. |
| CVE-2026-95818 | Same commit | Replace the old temporary-buffer normalization responsible for the loader overrun. |

The loader patch is adapted to 2.41's older dl-load.c, which predates
master's dl_scratch_buffer implementation. Its new dl-path-normalize.h is
verbatim upstream. The build fails if the patch neither applies nor is
already present. A build-only C regression check exercises representative
upstream normalization cases beside inaccessible guard pages. Final-image
verification initializes the resolver in fresh subprocesses with two long
LOCALDOMAIN search lists and requires success without a process abort.

Already carried by rcamarda2 and retained: CVE-2026-19499,
CVE-2026-5435, CVE-2026-6238, CVE-2026-19542, CVE-2026-77117,
CVE-2026-80489, CVE-2026-18374, CVE-2026-6791, CVE-2026-6368.
Version-range scanners can still report these backports; changing a version
suffix does not establish scanner clearance.

Remaining libc records:

- CVE-2026-97399 affects the Power8 strncasecmp implementation. This
  repository publishes linux/amd64; that architecture-specific code is not
  the image's implementation. No library removal or suppression is used.
- CVE-2026-89092 concerns nscd. The image does not install/run nscd.
- CVE-2018-20796, CVE-2019-9192, CVE-2019-1010022 through
  CVE-2019-1010025 and CVE-2010-4756 remain in Debian's open unimportant
  issues. Keep them visible; their status is not proof that every application
  use is safe. In particular, removing libc-bin never eliminates a scanner
  association with the still-installed libc6 package.

## GCC: one CVE, four package associations

CVE-2026-102010 is fixed upstream by GCC commit
`aaa8351f4d2e636f9680a1f0a8ebc2f0a60611e6`. It changes a C++ template in
`include/ext/pb_ds/detail/binary_heap_/erase_fn_imps.hpp`, assigning
`m_a_entries = new_entries` after reallocation. This is compile-time header
code, not four distinct defects in the four runtime shared libraries.

Rebuilding libgcc/libstdc++ shared objects with that header patch
alone does not prove a prebuilt ONNX wheel is fixed: an affected template
instantiation would have to be located and its consuming binary rebuilt.
No fixed Trixie GCC package is listed by Debian at this review. We retain
required libraries and do not claim the three retained-package rows are remediated or
unreachable. Future clearance requires vendor/package updates or evidence
about the wheel's compiled template use.

## Unused OpenMP runtime removal

The Dockerfile explicitly installed libgomp1, but the pinned Linux AMD64
ONNX Runtime 1.28.0 wheel has no libgomp DT_NEEDED entry. Its native binaries
require libc, libstdc++ and libgcc_s instead. NumPy 2.5.1 and its bundled
OpenBLAS/libgfortran/libquadmath shared objects likewise do not require
libgomp. Gnosis LocalEmbedder's CPU path invokes tokenizers, NumPy and ONNX,
with no direct libgomp load. Remove the unnecessary explicit install.

The build fails closed on installed Debian Depends and Pre-Depends,
including alternatives and multiarch names, queried directly with dpkg-query.
This avoids relying on already deleted apt lists and rejects query errors.
It checks every installed /usr/local shared object's ldd closure after
deleting unused optional Python extensions and before removing apt/ldd.
The base image also contains an unusable _tkinter extension with absent Tcl/Tk
libraries. Gnosis does not use a GUI; remove that extension instead of adding
Tcl/Tk runtime dependencies, and assert its final absence.
Any libgomp dependency or unresolved library fails the build. Final package
and library absence are asserted. The minimized image must also run real
offline embedding inference, producing a finite normalized 384D vector,
without libgomp in the process mappings. This removes one reported package
association; it does not resolve the GCC advisory against the three retained
runtime packages.

## Dash and tokenizers

Debian Dash 0.5.12-12 is configured with `--disable-fnmatch`; that selects
the recursive internal matcher described by CVE-2026-102473. The build now
repackages the same Debian source as `0.5.12-12+rcamarda1` with the existing
`--enable-fnmatch` option. This delegates matching to libc instead of adding
a new matcher implementation. Debian patches and remaining configure options
stay intact. Build assertions require HAVE_FNMATCH and the actual final Dash
binary's undefined fnmatch symbol. Final-image checks exercise an adversarial
multi-star mismatch under a five-second timeout and an ordinary bracket/glob
match. Dash remains installed because Docker health checks require /bin/sh.

CVE-2026-102474 describes a Unicode escape encoder in printf. The reviewed
Debian 0.5.12-12 source (including its patches) contains no such encoder:
conv_escape handles octal and single-character escapes, not Unicode u/U
conversion. Both Unicode-form escapes must remain literal in the final-image
regression. This is an applicability finding rather than a version-based fix;
retain the scanner record until Xray confirms the disposition. Evidence:
https://deb.debian.org/debian/pool/main/d/dash/dash_0.5.12-12.dsc
https://deb.debian.org/debian/pool/main/d/dash/dash_0.5.12.orig.tar.gz
https://deb.debian.org/debian/pool/main/d/dash/dash_0.5.12-12.debian.tar.xz

The public 0.23.1/0.23.2 tokenizers wheels remain affected by
CVE-2026-85670. This build creates `0.23.1+rcamarda1` from the SHA-256-pinned
0.23.1 PyPI sdist and its Cargo.lock, retaining the Gnosis-supported API.
The narrow downstream patch validates that the continuing-subword prefix
ends on a UTF-8 boundary and fits the second token, then rejects a merged
length exceeding the vocabulary-sized scratch buffer before writing it.
It returns the existing MergeTokenOutOfVocabulary error. This avoids the
reported overflow/panic, prefix subtraction underflow, and unchecked UTF-8
boundary. Rust and maturin are builder-only, and the original wheel is
replaced before the runtime is copied.

Final-image regression checks require ordinary exceptions for the upstream
malicious merge, a too-short prefixed token and a split UTF-8 character;
PyO3 PanicException, process abort or accepting these merges fails the build.
A valid BPE merge and the actual bundled model tokenizer must still work.
Remove the downstream carry when an upstream supported release contains a
verified fix. Xray may still associate the custom local version with the
upstream affected range; the suffix itself is not remediation evidence.

The bundled default model limits the normal input path but does not fix the
library. It is fetched from mutable Hugging Face main and its cache is
writable by the service account; previous documentation's claim that this
tokenizer is checksum-pinned was incorrect.
