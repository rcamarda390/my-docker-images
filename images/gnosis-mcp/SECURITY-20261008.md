## Permanent validation

The existing final-runtime validation now also runs
`verify-security-runtime.py`. It adds no dependency and does not change the
carried source fixes or package versions.

- CVE-2026-19499: put the 100-byte destination immediately before an
  inaccessible page, call strfmon and strfmon_l with `%100n`, and require
  E2BIG without an overrun. Ordinary formatting must still work. This follows
  upstream BZ 34510 and the regression included in the already-carried commit
  5256941bc811248670eda4636dccd0a390d34dec.
- CVE-2026-5435: use a TSIG record whose error code is 65535, check all output
  buffer sizes 1 through 256 against a trailing canary, and require upstream's
  unknown-record fallback. The already-carried resolver patch adapts upstream
  release/2.41 commit 0e8c56b386d72ba2ddf15784423f2e894c63a241.
- CVE-2026-95619: call the installed libstdc++ nonthrowing aligned-new ABI with
  the upstream size/alignment cases; require null for oversized allocations
  and a correctly aligned pointer for an ordinary allocation. The nonthrowing
  entry point catches C++ exceptions internally.

All checks passed with the v10 libraries and Python 3.13. As negative controls,
the same unpatched Debian libc6 2.41-12+deb13u4 caused SIGSEGV in the monetary
guard-page test and an assertion abort in the resolver boundary test. This
demonstrates the checks distinguish the carried fixes from stock Trixie libc.
Disassembly of the published libstdc++ operator-new symbol independently showed
its call to posix_memalign.

## Remaining boundary: CVE-2026-102010

The upstream fix adds `m_a_entries = new_entries` to
`include/ext/pb_ds/detail/binary_heap_/erase_fn_imps.hpp` after reallocation.
That template becomes part of the binary that instantiates it. The final image
has no GCC development headers or compiler. ONNX Runtime 1.28.0 source, tag commit
da9b5e364c465de65c49d91e696cd6485270757f, contains no references to `pb_ds`,
`__gnu_pbds`, or `binary_heap_tag`. Those identifiers also were not found in
the published /usr/local native dependencies or Debian runtime library files.
The ONNX source archive SHA-256 inspected was
9616cbdbbfcb1420b3261cd280a047d74ab0a249825e577b0e2dd310e22f6b83.

These are supporting applicability checks, not proof of the complete build
provenance of every stripped precompiled wheel and its transitive native
dependencies. Do not claim the whole image is free of this CVE. A confirmed
affected consuming binary must be rebuilt with the patched header; a shared
library replacement or new version suffix is insufficient.

No new rcamarda revision is justified: the reported glibc source defects are
already fixed and demonstrated above. Keep the stable Trixie base and existing
required native libraries. A new Xray scan or scanner-side review of the
backport evidence is still required for finding clearance. Nothing is suppressed
or hidden by this change. The existing image workflow validates the PR without
publishing and assigns the next immutable tag after an authorized merge.
