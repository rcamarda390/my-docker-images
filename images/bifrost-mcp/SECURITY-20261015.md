# CVE-2026-108859: mcp-go POST body buffering

Report: Xray, `bifrost-mcp:2.3.0-v1`, module
`github.com/mark3labs/mcp-go:0.56.0`, CWE-770. Digest, score and fixed version
were not supplied. Scanner clearance remains pending.

## Diagnosis and treatment

The vulnerable entry point is `StreamableHTTPServer.ServeHTTP`: it calls
`io.ReadAll` before content/session/JSON validation. Upstream v0.56.0 has no
body cap. The CNA record names releases through v1.2.1; direct review of
v1.3.0 also finds the unbounded read. No verified official fixed release.

This repository already carried the source fix in commit
`26c4c01` before the 2.3.0 bump. Do not claim this report discovered a missing
patch, or change module metadata to make a scanner stop reporting it.
The existing patch caps reads at 100 MiB using `http.MaxBytesReader`, rejects
oversized declared lengths without reading, and returns HTTP 413 for oversized
unknown-length bodies. Bifrost is compiled from that private vendor tree.

Patch SHA256:
`cfe4c01fa01e4aca398475eaa46c4942e5264fda205106ec2503eae73b4d3004`.

This follow-up retains the fix, expands regression coverage to zero and
understated ContentLength, makes test output visible in build logs, and asserts
the mcp-go version in the actual final binary's Go build info. Normal MCP
initialization remains covered. The per-request ceiling is unchanged; it is
not a global concurrent-memory budget.

Revision metadata becomes 2; the existing publication workflow chooses the
next unused 2.3.0-vN tag from published tags. No workflow change.
